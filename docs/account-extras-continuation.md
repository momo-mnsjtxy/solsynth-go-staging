# Paid name cards and annual account rewind

This slice is based on committed continuation `31710ae1907017446a7c1b5c836cc202a60aa4be` plus the frozen account-settings overlay and its notification field merge. It preserves those artifacts. Complete licensed authored source is verified by the manifests under `ports/passport/namecards/source` and `ports/passport/rewind/source`. No excluded Shared/Spec/generated SDK, Jieba dictionary, fortune corpus, artwork, live payment, messaging provider or production identity was used.

## Paid name cards

The licensed controller establishes `GET /api/accounts/me/name-change-card`, `POST /api/accounts/me/name-change-card/order`, and `POST /api/accounts/me/name-change-card/use`. The owned gateway aliases use `/stargate/accounts/me/name-change-card`. Order has no required body and returns `{purchase_id,order_id,amount}`. Use accepts only `{target,target_id?,new_name}`; target is account, realm or publisher. Lists accept bounded owned `take`/`offset` pagination and return `X-Total-Count`. The source caller polls fulfilled/consumed timestamps in the purchase DTO. The controller, full service, options, DTO, payment-event metadata and full Solian purchase/use sheet are retained.

Source defaults are 100 points, one order per rolling 30 days, with every created order counted even if unpaid. The implementation requires explicit operator price, purchase-period/limit, points-currency and payee-wallet configuration. There is no inferred points currency, free entitlement, HTTP fulfillment endpoint or callback/body claim. Creating an order does not debit anything. Payment uses the existing commerce checkout authorization and PIN path. Under its existing transaction, the canonical wallet hold must settle successfully before the typed fixed-product hook records a matching order/purchase/transaction receipt. Missing fulfillment configuration or any receipt/audit failure rolls back the hold and settlement. Replay returns the same existing payment; funds move once.

`commercepg.CreateNameCardOrder` is a narrow same-pool transaction helper for `passport.name-change-card`. It creates a canonical internal order and outbox record with the configured amount, currency and payee. `NameCardRequest` reuses `commerce_v1.idempotency`; optional `Idempotency-Key` is actor-scoped and payload-bound. Source callers without the header retain source behavior: order retries are subject to the purchase quota, and use takes the oldest available card. Concurrent use is serialized by the canonical account and card locks. Failed validation/role/name/receipt writes consume nothing. Exact same-name no-ops are rejected without consuming another card.

Account rename accepts the source's 2–256 ASCII letters, digits, underscore and hyphen. UUID-shaped names and current reserved account-route references (`me`, `verify`, `verification`, case-insensitive) are rejected. Signup keeps its existing narrower registration rules. Sign-in and trusted lookup reference bounds are 256 and lookups use case-folded names; the existing account schema's `lower(name)` uniqueness index is reused. Existing collisions cause the explicit account migration to fail instead of silently rewriting identities. A successful account rename advances canonical account version in the same transaction, invalidating old sessions/delegated proofs. The account profile editor's exact unchanged name is stripped before ordinary metadata validation, so short, hyphenated and long renamed names can still save profile metadata.

Publisher rename uses the canonical publisher lock, current Manager-or-higher membership, `publishers.update`, and current organization realm membership. It preserves existing publisher syntax/reserved-reference rules. Any federation registration, including disabled registration, rejects a changed name until an actor-URI migration exists; the card remains available. The optional federation table is checked inside the publisher transaction. Ordinary publisher PATCH still rejects changed names while accepting an exact unchanged name with metadata, with a locked repository recheck.

Realm card use is source-supported only for the canonical owner with current Owner membership and `realms.update`; existing slug syntax/reference rules remain. The source also explicitly allows free moderator slug changes in ordinary `RealmController.Update` (lines 846–851). That overlapping free PATCH is preserved. It is not labeled a paid-card bypass or converted into a new paid-only policy. Ordinary account and publisher name changes retain their evidenced card boundary. Global-admin rename is a separate moderation policy and is not called here.

Lock order is canonical account, commerce request/card/order state, then existing realm/publisher ancestry and target locks. Commerce payment retains its established order/wallet locking and rechecks payment authorization after settlement waits before fulfillment. Rename adapters recheck authorization after conflicting-name waits and retain the current role boundary. Account version advances only after the final proof check. The original proof is used when recording use idempotency before rename; all writes still commit or roll back together. Timestamps use the shared configured clock truncated to PostgreSQL microseconds. All repeated parameters, nullable scans and schema dependency order were audited.

## Annual rewind

Rewind is an annual activity report, not identity rollback. The controller exposes public `GET /api/rewind/{code}`, authenticated `GET /api/rewind/me`, and authenticated `POST /api/rewind/me/{year}/public|private` with `rewind.create` for sharing changes. Gateway aliases use `/stargate/rewind`. No active Solian rewind caller exists in the inspected pinned tree; backend controller, full aggregation services, local model, sphere/messager services and full chat top-member helper establish this contract.

The source uses a December 26 UTC start in the preceding year and December 26 UTC exclusive end in the named year. Its creation hardcodes 2025 while lookup/model use the current year. The owned implementation uses one explicit reporting year (configured, or current UTC year) consistently. It creates one durable immutable snapshot per canonical account/year. Concurrent GET generation has one winner and audit failure rolls the snapshot back. Names, profiles, posts, publishers and rooms are not copied into snapshots: only measured values and canonical reference IDs are retained.

Source fields retained:

| Component | Source fields and owned behavior |
| --- | --- |
| passport | `max_check_in_streak`, `check_in_completeness`, `new_friends_count`, `new_blocked_count` from canonical check-ins/relationships. The source's 365 denominator is retained, including leap years. |
| passport activity | `most_active_day`, `most_active_weekday`, `latest_active_time` through the explicitly enabled current-Go canonical action-history adapter. Missing enablement is explicitly unavailable; legacy remote telemetry is excluded. The canonical history view controls original actor attribution and domain coverage. UTC day/weekday aggregation is retained; local clock time uses the actual instant, correcting the source's discarded-time bug. Before-06:00 preference is preserved. |
| sphere | `total_post_count`, `total_upvote_count`, `most_popular_post`, `most_productive_day`, `most_loved_publisher`, `most_loved_audience` from current canonical member/visibility scopes. Productive-day dates use the owned ISO date representation. Ties are deterministic. |
| sphere words | `top_words` through the real locally configured dictionary tokenizer, bounded to 1 MiB input, 1,000 posts, 200,000 consumed tokens and 100 validated output words (operator limits may be lower). The tokenizer software is implemented; no dictionary is bundled or remotely fetched. Missing dictionary or over-limit input is explicitly reported as an unavailable component. 1,001 visible source posts are detected rather than silently truncated. |
| messager | `most_messaged_chat`, `most_messaged_direct_chat`, `most_called_chat`, `most_called_chat_top_members` (source top three), and `most_called_accounts` (source top three) from canonical message/call records and current room access. Call duration is nonnegative elapsed whole seconds, bounded to the report window and creation instant. |

The response has source `schema_version:1` fields plus explicitly owned `projection:"owned-partial-v1"` and `unavailable_components`. Optional-provider absence is visible and never presented as complete original parity or fabricated content. Configured adapter tests use real canonical SQL history and the real dictionary tokenizer on synthetic owned input; no remote telemetry or dictionary retrieval occurs. Historical snapshots remain immutable when host configuration changes; Rewind does not silently backfill or migrate an existing report.

Every report read rehydrates referenced posts with `postpg.ReadWithVisibility`, publishers with canonical viewer predicates, and rooms with current relation/membership gates. Same-pool account/chat helpers join the report transaction. The incoming moderation gates therefore apply through those helpers. Source private-post or removed-room references cannot survive as cached DTOs. Shared reports omit all private DM/call references and participant lists. Word aggregates are owner-only because their source snapshot can include private posts; shared responses explicitly identify that redaction. Aggregate owner statistics may be shared, with current accessible public group/post/publisher references only. Profile birthday and private contact data are never hydrated.

Public share codes contain 192 random bits, are bounded to 32 URL-safe characters, and change on each source-style public action; prior codes stop working. Private removes the code. Public reads lock canonical account then report, recheck current disabled/punished state, and serialize with sharing/disable changes. Responses are `no-store`. A blocked public read cannot use a code removed before its account lock is acquired. Unsupported encrypted room references are omitted; their content is never exposed.

## Host and schema wiring

The patch deliberately does not edit the host, installer or deployment configuration. Parent integration must:

1. Apply `internal/namecardpg/schema.sql` after existing authority, account (including folded-name index), social, wallet and commerce schemas. Apply `internal/rewindpg/schema.sql` after authority and its source-domain schemas (profiles, social, progression, posts/interactions, chat relations and calls). Include both schemas in the guarded before/after restart harness. No constructor executes DDL.
2. Construct `namecardpg.New` with the host's exact database/guard, canonical commerce repository, `accountpg` configured with canonical realms, and canonical `socialpg`. Supply an explicit enabled points policy/payee and the same clock as authority/commerce. Configure `commerceRepo.WithNameCards(cards)` before starting requests/workers. Include `cards.Ready` in readiness.
3. Route `namecards.RouteMatches` before generic accounts and mount `namecards.Service{Repository:cards,Authority:verifier}`. Keep the existing commerce payment handler, payment policy and PIN verification. Do not expose the internal fulfillment helper separately.
4. Construct `rewindpg.New` with the exact database/guard, canonical account repository with realms, canonical chat repository with social/room policy, canonical post visibility provider, and shared clock/report year. Enable `Options.CanonicalActionActivity` to use the already installed `owned_account_action_history` view; apply `internal/accounthistorypg/schema.sql` (the final identity/history slice extends its canonical coverage) before readiness. Supply `Options.Dictionary` with a valid local dictionary to construct the real tokenizer, or pass a previously validated immutable tokenizer. Ambiguous real/custom provider configurations fail construction. Include `rewind.Ready` in readiness and route `rewind.RouteMatches` to its service.
5. Preserve incoming moderation's account/publisher/post predicates and the frozen account-settings field overlay. Name-card helper changes are separate from the moderation worker's privileged admin rename.

The compile-only utilities dependencies listed in `docs/account-extras-compile-dependencies.json` are already present in current continuation and excluded from the delivery patch. They support the renamed-account autocomplete regression; they are not a second utilities delivery.

## Configured current-Go activity and dictionary segmentation

`--enable-rewind-action-activity` activates the same-pool canonical account-action history adapter. It reads only the report actor's original attributed `created_at` values in the December 26 UTC window, orders deterministically, and detects the 100,001st event instead of reporting an arbitrary prefix. `Ready` requires the actual history view columns. Coverage follows that view's canonical domain-audit sources; it does not infer login activity, import remote telemetry, or claim that missing historical events exist. The final identity/history integration supplies the reviewed expanded view; this adapter does not copy its unreviewed code.

`--rewind-dictionary=/absolute/path/dictionary.txt` activates an immutable in-memory dictionary tokenizer. UTF-8 non-comment dictionary lines are `word positive_frequency [part_of_speech]`. Frequencies are positive integers up to 10^12; duplicate lowercase words, invalid Unicode, control characters, punctuation inside words, words over 64 runes / 256 bytes, excessive entries/bytes or more than one million trie nodes fail startup. Blank lines and lines starting with `#` are ignored. `--rewind-stop-words=/absolute/path/stop.txt` loads one validated lowercase word per line. Optional `--rewind-dictionary-sha256` and `--rewind-stop-words-sha256` pin exact lowercase SHA-256 digests. Paths must be absolute and clean. Descriptor-relative `O_NOFOLLOW` parent traversal and nonblocking final open reject ancestor/final symlinks, directories and special files; reads are capped before allocation. No network or HTTP path can select a file or vocabulary.

Han runs use dictionary DAG edges and a maximum log-frequency path, with unknown single Han characters as fallback edges. Other Unicode letters and digits form lowercase continuous tokens; punctuation/emoji split tokens. Single-rune tokens, tokens over 256 bytes and explicit stop words are omitted; all consumed tokens count toward the limit. Counts sort descending, then word bytes ascending. This deterministic owned software contract does not emulate the excluded original Jieba HMM or assume a license for its dictionary. All dictionary I/O happens during host construction, outside SQL transactions. Readiness and concurrent requests use the frozen trie even if the original file is later removed.

Operators may lower `--rewind-max-input-bytes` (1..1048576), `--rewind-max-texts` (1..1000), `--rewind-max-tokens` (1..200000), `--rewind-max-dictionary-bytes` (1..16777216) and `--rewind-max-dictionary-entries` (1..200000). Input/rune arrays, DAG traversal depth (64), consumed tokens, unique counts, sorting and dictionary memory are bounded; segmentation checks request cancellation. No partial token prefix is saved when a bound is exceeded.

Report generation captures authorized current text, commits that read transaction, and computes word counts with no SQL account locks held. A new transaction reauthenticates the original proof, recaptures all current metrics/visible text, and requires an exact text-input match before storing the immutable snapshot. Corpus edits cause a bounded outside-lock retry; sustained changes return unavailable without a snapshot. Final authenticated reads/sharing recheck the original proof after all reference hydration. Public reads recheck current disable-account state after hydration and always redact private text aggregates.

New actual PostgreSQL contracts are `TestPGRewindActualCanonicalActivityDictionaryHostAndPrivacy`, `TestPGRewindActualAdaptersBoundedCorpusAndActionRows`, `TestPGRewindConfiguredOriginalProofRevokedWhileAccountBlocked`, `TestPGRewindTokenizerReleasesAccountLockAndRevalidatesOriginalProofAndCorpus`, and `TestPGRewindConfiguredAdaptersSavedRestartPersistence`. They require private CI; ordinary unit/race/vet or integration compilation do not execute them. The new strict restart case uses its own sealed-template database, an original one-hour proof created before all target publisher/post/report state, an exclusive `rewind-configured-adapters.json` marker and `rewind-configured-dictionary.txt` file with a saved digest. After restart it opens the original OID, reconstructs a public-key-only verifier, reloads the pinned dictionary, and checks exact original report/action rows and owner words/public redaction without DDL, reseeding, issuing credentials, creating a new fixture, repairing snapshots or changing expiry.
