# Developer media and quota continuation

This source-backed slice adds canonical app/product/bot picture and background associations and GET /api/develop/quota. It is an owned continuation, not a claim of complete upstream quota or file-service parity. No provider, credentials, network activation, production data, or excluded generated/shared definitions were used.

## Contract evidence and exact limits

The retained authored DysonNetwork controllers/services at 4ee2d0cebb9da8284a92483fee6dce795bf6947c establish the app/product/bot picture_id and background_id request fields, file lookup and nested file projection. App and product update code calls resolution only for non-null IDs, so omitted/null IDs retain their slot. The bot service clears the optional RPC request field when its argument is null; the receiver implementation is not retained, so bot null retention is an explicit owned policy rather than a claim about the excluded RPC implementation. Existing authored Solian models establish the app picture/background and nested bot account fields. Exact retained file hashes and manifest references are in developer-media-quota-source.json.

The quota controller authenticates the account and returns an unretained ResourceQuotaResponse<DeveloperBotQuotaRecord>. The authored bot create controller consumes Total and Used. The formula, record shape, bonus/paid-tier calculation, and account-to-resource aggregation are not established by retained licensed evidence. This implementation returns only the evidenced lowercase total and used numbers. It does not invent records, base/bonus values, or aggregate a user's publisher memberships.

## Explicit owned quota policy

Existing canonical bot admission uses owned_bot_quotas, one configured capacity per publisher. The new empty-by-default owned_developer_quota_accounts table explicitly binds an account to exactly one existing publisher capacity. The endpoint requires the original authenticated account proof and current direct ownership of that individual, live developer publisher. The binding is configuration, never discovered from membership or automatically created by enrollment, schema installation or reads.

A missing binding, missing/not-yet-current/expired capacity, or unconfigured quota adapter returns 503. A binding to another account's publisher returns 403. Successful reads expose total=bots_total and used=the same non-deleted bot reservation count used by admission. Soft-deleted app/project ancestry does not free live bot reservations; explicitly deleted bots do. Miniapp capacity is separate and is not included. This deliberately narrower account-to-publisher mapping requires operator configuration and is not exact upstream account-wide quota parity.

Quota reads lock account proof, explicit binding, publisher, then capacity. Admission locks the same publisher/capacity and observes wall time after the capacity wait. Bot creation rechecks current capacity expiry after media and audit waits; expired admission rolls back account/profile/bot/media/audit effects together. Reads issue no new proof, grant or capacity.

## Canonical media and privacy

The explicit owned_developer_media schema stores kind (app/product/bot), resource, slot, canonical file, uploader and attachment time. It stores no bytes, URLs, quota ledger or cached file snapshot. Apply runs inside the resource's existing transaction after actor and ancestor locks. It accepts only ready canonical PNG/JPEG/GIF/WebP/AVIF/BMP files uploaded by the actor, locks both selections in UUID order, and never treats public visibility or membership as file ownership. Canonical UUIDs are an owned difference from source opaque file-ID lengths. Empty strings are rejected rather than treated as removal. There is no invented slot-delete route; source null retains the slot and resource deletion removes that resource's slots.

App/product writes repeat current publisher/member/owner checks after media and audit waits, and repeat the original account proof immediately before commit. Bot writes retain their existing sorted account locks, current owner validation and original-proof checks; updates repeat target-account moderation at current wall time after waits so a scheduled punishment cannot be missed. Mutation responses resolve nested media after audit waits, including a retained slot whose original uploader differs from the current actor. A failed file lookup, foreign uploader, invalid MIME type, quota, audit or commit rolls back the whole mutation. The product/commerce document contains no captured file metadata; every response resolves current metadata through the adapter.

A canonical private file gains only the resource audience: live production app and unshadowbanned individual publisher with active direct owner; enabled product for public product images; active, unpunished bot account for public bot images. Current joined publisher members may read managed private/disabled images. The canonical file must remain ready with its same active, unpunished uploader. Deletion, status withdrawal, member revocation, owner/uploader disablement or punishment, product disablement and bot deactivation are observed afresh by the media byte route, including after canonical file and object-store waits. A file's independently public flag and uploader access keep their existing media meanings. Other independently authorized resource links can still grant access; removing one link does not revoke another resource's grant.

Bot images are nested in the managed/public bot response's account.profile. They do not populate ordinary account-profile media slots, which would inadvertently expose private bot media through the generic account profile. App discovery's existing narrow AppDiscovery projection is unchanged; full app/product/bot resources carry current picture/background fields.

## Composition and verification

Install internal/developmediapg/schema.sql explicitly after canonical media/apps/bots. internal/botpg/schema.sql adds the empty quota binding table. Constructors perform no migrations. The host supplies the same developer media adapter to app and bot repositories and to canonical media visibility. Without media storage configuration, non-null media writes remain unavailable; ordinary metadata writes still work. Media readiness follows the existing composed media dependency chain, and bot readiness verifies the new quota binding schema.

Twelve named real-PG tests cover composed routes, metadata/bytes, source null retention, ownership/readiness failures, rollback, current audience, file-wait privacy withdrawal, original proof expiry on both media writes and quota reads, owner disablement after file/audit waits, retained-uploader disablement during app/product/bot audit waits, scheduled bot punishment after file/audit waits, current quota policy and bot admission expiry. These cases require actual private-CI execution. The restart test writes an exclusive 0600 synthetic marker with original app/product/bot/file state, original token and public verifier snapshot before shutdown; after restart it creates no fixtures, tokens, grants or policy and checks the same IDs, JSON, file bytes, quota and audit count through reconstructed repositories and host.

Offline compilation, unit/race/vet and static SQL checks do not establish actual PostgreSQL, lock, restart or existing-client interoperability behavior. These cases require the coordinator's guarded disposable private-CI runner and independent integration grouping review. Miniapp package upload/replies/credentials remain outside this slice.
