# Signed quote authorization continuation

This bounded addition starts from `5815f5558f8b1a3e97ebf17301bb4d5d94f90283`. It adds an inbound quote consent lifecycle to the existing canonical publisher/post, HTTP-signature, pinned-peer, replay, and durable-delivery implementation. It does not implement unrestricted federation or remote identity discovery.

## Supported flow and routes

1. The local publisher has explicitly opted into federation. Its manager has established an accepted outgoing follow to a preprovisioned remote actor. An earlier signed public Note has established that exact actor's ownership of the prospective quote object in this recipient's existing remote cache.
2. That actor sends a signed QuoteRequest to the local publisher's normal inbox. `object` must identify this publisher's canonical, currently public, published, non-draft, non-deleted, non-shadowbanned, non-realm post. `instrument` is the exact previously established remote Note URI, or a Note object containing that URI. Its origin must exactly equal the signed actor's origin; any supplied attribution must match the actor.
3. The inbox transaction records an immutable authorization, its original request ID, remote actor/key fingerprint, target audit revision and quote object. It enqueues an Accept with `result` set to the authorization URI and commits replay state with those effects. Same activity/digest replay is idempotent. A changed replay or second request reusing that quote object conflicts.
4. The remote actor can send a signed Update of that same public Note with `quote` and `quoteAuthorization`. The adapter verifies every binding and records its first consumption time. Further updates may retain the same binding; another object, author, target or stamp is forbidden. This is one authorization for one immutable quote-object binding, not a transferable bearer capability.
5. GET `/quote-authorizations/{uuid}` returns the sourced JSON-LD projection only while every current check passes. The response identifies the stable anchored author, quote object and canonical target. No target text or private content is included.
6. DELETE `/quote-authorizations/{uuid}` uses the existing authenticated `publishers.update` proof and current canonical publisher manager/owner membership. It permanently revokes the stamp, removes cached quote approval fields, cancels pending/inflight acceptance and atomically queues a content-free Delete. Repeated revoke creates no duplicate notification. Revocation itself still succeeds if current remote key lookup is unavailable or the destination has been removed from the egress allowlist. A now-disallowed destination suppresses notification instead of rolling back local withdrawal; otherwise the delivery worker verifies the pre-existing pinned destination and current peer before sending.

Root GET uses the public federation handler. Root mutations pass through the host's existing identity and transaction-authority binding before reaching the handler; the original signature-covered inbox route is unchanged. Unauthenticated DELETE is rejected. The legacy POST `/quote-authorizations` remains an explicit unsupported authenticated operation because its bearer-subject-to-remote-actor mapping does not prove quote ownership. No unsigned substitute grants authority.

## Current policy, locking and recovery

The existing actor-account then canonical publisher lock serializes grants, local revoke, block/unfollow, disable and delivery. Quote admission/consumption/acceptance delivery also locks the canonical target post, checks live owner disable punishments with the database clock, and compares the target's audit sequence and update timestamp. A private transition followed by republication cannot reactivate an old stamp. This deliberately conservative owned policy also invalidates a stamp after a benign target edit; a new quote object and request are required for the newer revision.

A grant requires current allowed-origin/key ownership, current accepted outgoing follow, matching cached public Note ownership, and no block. Key ID plus public-key SHA-256 binds the authorization to the key that signed its request. An observed different current key permanently revokes the old stamp and cancels unsent acceptance; restoring that older key cannot reactivate the observed-invalid grant. A lookup outage alone fails closed without declaring a new key version. The provider exposes no generation/history, so a rotation and rollback occurring wholly between observations remains outside this guarantee. The inbox rechecks the current provisioned actor/key and the five-minute signed-date window after obtaining the publisher lock and again after all later waits before commit. Verified proofs and retained remote keys snapshot their RSA public modulus, so provider or accessor mutation cannot rewrite a proof binding. Public grant dereference resolves an initial key before its current read-committed transaction, locks canonical account/publisher/target rows, and rereads revocation, privacy and revision. Target row acquisition and target/audit policy reads use separate SQL statements so the latter snapshot begins after a lock wait.

Block, unfollow, explicit federation disable and remote quote-object deletion permanently revoke affected grants. In particular, follow or cache delete/recreate cannot revive a prior grant. Privacy or target revision changes make both dereference and unsent acceptance fail closed. Direct administrative database changes remain outside the application mutation contract.

A delivery's new quote foreign key distinguishes quote Accept/Delete from Follow Accept and post Delete. The normal lease token, retry, pair ordering, pinned destination, RSA-SHA256 signing, current publisher/owner and block checks remain in force. A stale authorization cancels its acceptance before transport, with another current check after delivery-lease and signing-key waits. An inbound Undo of a Follow cancels only Follow acceptance (`quote_id IS NULL`), preserving independent quote consent. Revoke waits behind any already-running send under the same publisher lock, then sends the ordered withdrawal. No remote transport starts during construction or an inbox/management request. The existing explicit delivery worker owns network calls.

Install `internal/federationpg/quote_schema.sql` atomically after canonical posts and the base/identity federation schemas. One new owned authorization table and an additive delivery foreign-key column are included in `federationpg.Schema` for disposable fixtures. Constructors never migrate. Readiness checks require the relation and column. The private runner and its schema-order/atomicity controls include the migration.

## Validation and bounded gaps

Six required PostgreSQL declarations cover lifecycle and one-object reuse, current privacy/origin/ownership, key freshness/rotation and block/unfollow revocation, concurrent replay plus inbox/audit rollback, actual restart persistence, waited-for privacy/revocation/audit/signature age, observed key rollback, egress removal and Follow/quote acceptance isolation. The restart before phase saves exact grant and outbox prestate with the parent's exclusive marker helpers; the after phase only reads and compares it. The fixture explicitly disables its publisher and cancels transport work before saving the marker so unrelated global workers cannot consume its queue. Active-versus-revoked grant records and exact durable payloads are preserved; this does not claim an enabled actor was exercised after restart.

Pure Go tests check signed instrument immutability, post-verification expiration, root GET versus protected mutation routing, projection, and revoke dispatch. Full offline verification covers source integrity and mutation rejection, PG16 grammar, runner/result controls, formatting, build, vet, all Go tests and the full race suite. Actual PostgreSQL transaction/catalog/locking/restart outcomes remain for the authorized private CI; local integration cases are compiled skips, not database passes.

Unsupported remote authorization references are rejected, not trusted as permission. The client must reverify a stamp to observe current availability.
