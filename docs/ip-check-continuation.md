# Caller IP and geographic lookup

The licensed authored `inventory/operation-sources/DysonNetwork.Passport/IpCheckController.cs` at DysonNetwork commit `4ee2d0cebb9da8284a92483fee6dce795bf6947c` (Git blob `f70b161ecb51097cd5aa334515bb9bb9e7e80188`) establishes GET `/api/ip-check/geo`, the authenticated diagnostic GET `/api/ip-check`, and the nullable geographic/diagnostic DTO fields. The authored [permission registry](https://github.com/Solsynth/DysonNetwork/blob/4ee2d0cebb9da8284a92483fee6dce795bf6947c/docs/PERMISSIONS.md), blob `524bc9fd360bd3e358ffc108cbf60823bd734361`, establishes `admin.ip.check`. No generated protocol code or original geographic data is used.

The independently owned diagnostic policy requires the current canonical Superuser flag and that exact permission through the existing verifier. Role headers confer no authority. Responses are no-store. Header output retains only bounded forwarding metadata and ordinary negotiation headers, excluding Authorization, Cookie and API-key fields. This intentional redaction differs from the source's unrestricted header dump.

The network peer is authoritative by default. Forwarded client IP is considered only when an operator explicitly configures both trusted proxy CIDRs and one supported header. X-Forwarded-For is parsed as a bounded strict IP list and evaluated right-to-left while the immediate chain remains trusted. Malformed or repeated selected headers fail closed; untrusted peers cannot select their IP through headers. X-Real-IP and CF-Connecting-IP require one IP and the same trusted-peer boundary. Broad zero-bit proxy trust is rejected.

The concrete local provider consumes an explicitly configured JSON file with `revision`, `provenance` and `entries`; each entry has `prefix` and `geo`. Lookup uses the longest matching canonical CIDR. Input is bounded to 32 MiB and 100,000 unique prefixes, with strict unknown-field rejection, finite latitude/longitude validation and copied immutable data. CLI flags are `--ipcheck-geo-file`, `--ipcheck-trusted-proxies` and `--ipcheck-forwarded-header`. No network access, provider default, geographic dataset or startup migration is introduced. Missing provider returns 503 for geo; misses and missing coordinates return distinct 404 failures. Zero latitude/longitude are valid coordinates.

This is an owned JSON CIDR provider format, not compatibility with the original MaxMind database/service implementation. A legally sourced operator dataset or future configured MMDB adapter remains necessary for useful real-world geographic resolution. No invented default country or location is returned. Diagnostics remain available to an authorized administrator without a geographic provider.

Local no-socket tests cover proxy spoofing, trust chains, duplicate/malformed headers, diagnostic authority/header filtering, dataset bounds/coordinates/longest-prefix matching and mutation isolation. `TestPGBackendIPCheckComposition` adds canonical PostgreSQL-backed identity and current Superuser revocation checks through the composed host. The new PG case remains a candidate until its exact published commit passes the guarded CI runner; prior 315/44 evidence does not establish it.
