# Calendar source evidence

The implementation is based on licensed authored controllers, eligible service methods and Solian callers at DysonNetwork `4ee2d0cebb9da8284a92483fee6dce795bf6947c` and Solian `ffd0838e5f04cb40bea311a39118ebeedad210c1`. Exact byte hashes, Git blobs, paths, URLs and licenses are in `ports/passport/notabledays/source/manifest.json`; five new source snapshots match their fetched Git blobs exactly. The complete AccountEventService.cs is omitted because it also contains unrelated fortune fallback prose. Its pinned URL and original hash remain metadata only in omitted_sources; no fortune prose is included. Four already-retained controllers/jobs and the canonical permission catalogue are referenced by their existing paths. The two repository AGPL licenses are retained beside the new snapshots.

The source family comprises regional notable-day catalogue CRUD, owned calendar events, private/friends/public visibility, subscriptions, recurrence, month/merged views, search, generated notable-day detail and countdowns. The authored callers establish visibility values 0/100/200; daily/weekly/monthly/yearly recurrence values 1/2/3/4, weekday names, tags and search-result type values. `PERMISSIONS.md` defines notable-day CRUD, calendar-event CRUD and `calendar.subscriptions.manage`. These documented canonical mutation keys are checked inside the Go transaction even where the source controller omits an explicit permission attribute.

There is no evidenced generic calendar reminder operation or reminder job. The retained `NightOwlReminderJob` concerns unrelated wellbeing activity; it was read only to establish that distinction. This delivery adds no reminder feature, notification state, external calendar connector, provider contact or duplicate account/progression authority.

The source lunar resolver uses `System.Globalization.ChineseLunisolarCalendar`, regular lunar months, a previous-lunar-year fallback and lunar month 12 day 30 fallback to day 29. Independently authored `oracle/Program.cs` calls that installed official public API to generate calendar facts and comparison results. It does not read/copy runtime implementation tables or excluded schemas/models. Go embeds only the factual year/month lengths and leap-slot table. The independent executable reproduces all 74,772 resolution cases across Gregorian years 1901–2101, including the partial final year, against .NET 10.0.12. Ordinary Go tests compare the exact digest.

The source contains three authored global markers: New Year's Day, Christmas and the Solar Network anniversary on March 16. These literals are preserved. No external regional holiday corpus or seed asset is imported; configured catalogue records are authoritative. Source calendar icon/background IDs are now connected to canonical media through the separately documented calendar-media continuation. The source's merged check-in/status numeric enum values were not established by the authored callers; the concrete host overlay exposes truthful daily fields and requires explicit verified wire values before adding those two merged item kinds.

See `notabledays-continuation.md` for behavior, intentional source corrections, host wiring and validation limits.

The newer full retained-source audit and independently authored activity projection are documented in `calendar-media-source-evidence.json` and `calendar-media-continuation.md`. The legacy HTTP merged activity numeric mapping remains unverified; the authored RPC countdown conversion is a distinct contract and is not reused.
