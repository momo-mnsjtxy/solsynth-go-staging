# Independent OAuth correctness review

Reviewed the immutable 22-file OAuth delivery at base `2e6e25f0a9ba31659119b5981338c08edde7bd43`, manifest SHA-256 `91eaf5610b05a614474a82ea89fcb08893e9133848858ccfd65957d257d8a834`. All source hashes matched before review. The original delivery remains unchanged. Both findings below were confirmed with its owner before preparing this separate patch.

1. **Stale preview could report success.** `internal/oauthpg/repository.go`, `Preview`, checked an existing request's hash/expiry/decision but omitted its stored app epoch and owner identity/version. Repeating a preview after those authority values changed returned current metadata successfully, although `Decide` would necessarily reject it. Preview now checks those three stored values against the same locked canonical boundary and denies a stale request. This fixes a misleading successful response; the existing decision path already prevented stale approval.
2. **Confidential credential purpose withdrawal was incomplete.** `internal/oauthpg/tokens.go`, `client`, checked the credential's purpose scope but did not require that purpose to remain in the app's current registered scopes. Canonical credential creation and ordinary app credential authentication both enforce that registration. Confidential OAuth authentication now also requires current `oauth.client.authenticate`; public clients remain secret-free and do not need it. App epochs already invalidated earlier grants, but this additional check is needed for fresh issuance after purpose withdrawal.

The patch changes only these two runtime files and adds two defensive integration regressions: `TestPGOAuthPreviewRechecksRegistrationAndOwnerVersion` and `TestPGOAuthConfidentialPurposeScopeWithdrawal`. The first covers app epoch, owner version and owner identity changes plus fresh-preview recovery. The second verifies confidential denial and continued public-client operation after marker removal. No app organization gate, host dispatcher, signing policy or original frozen artifact is changed.

Reviewed invariants: canonical account/session/proof binding; app/consent epoch and credential freshness; distinct delegated token-use lane; one-use code/refresh mutation under account locks; refresh/code replay revocation committed before returning denial; parent lifetime limits; sorted owner/user acquisition; NOWAIT secondary binding locks; nullable owner/credential/JSON scanning; SQL parameter types; cleanup lock behavior; and rollback-injection constraints. The reviewed paths use the canonical authority store and do not introduce resource scope delegation. No additional concrete defect was established in these areas.

Focused race tests passed for authority, OAuth transport, authority PG, app PG and OAuth PG packages. Focused vet and race-enabled integration compilation passed. The two new PostgreSQL tests have not been executed locally; parent GuardedPG execution is required. Only local synthetic defensive regression fixtures were authored. No live target, local PostgreSQL socket or external provider was used.

Host requirements remain those in the original delivery: keep OAuth token/userinfo dispatch separate from ordinary bearer middleware; preserve the parent's organization app gate; use the exact canonical pool/issuer/verifier/guard/app store; install versioned app/signin/OAuth schemas explicitly; and retain bounded maintenance. The patch is intentionally independent of current host composition.
