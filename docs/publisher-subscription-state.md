## Source and contract

`publisher-subscription-state-evidence.json` maps eight source controller actions to composed `/sphere` and direct `/api` routes, their retained authored source hashes, and ten named real-PG cases. The controller and native Solian creator/discovery callers establish route and request shapes. The authored service at pinned blob e1df7a8168b098b0cb166c626ebc7cc83dc339d5 is retained under `ports/sphere/timeline/subscription-source`; its hash and AGPL license participate in the offline integrity gate. The already-retained Sphere model snapshot independently confirms nullable last_read_at and ended_by_account_id. No protocol/generated binding, Socommon, canceled repository, Suki or fortune source was retrieved.

Managers (current joined role >=100 plus canonical publisher/realm authority) may list, add and remove subscribers. Only accepted, unended subscriptions appear. Pagination uses X-Total, stable created-at/ID ordering and bounded offset/take. Account hydration is the canonical public projection, without birthday, credentials or private authority state. Ended subscriptions stay durable. The source rejects manager addition for existing subscriptions, including accounts that voluntarily left or were removed; these conditions cannot silently force a resubscription. New manager additions have notify=false. Own subscribe may resume an ended row and resets notify=true, matching the authored CreateSubscriptionAsync implementation despite the stronger prose comment on manager removal.

Own notify/read requests always use verified principal identity, never a body/query/header account selector. Active subscription is required; missing/pending/ended rows return 404. Explicit last_read_at is a valid supplied instant or current database time for null/omitted values, as the source service specifies. Notify omission retains the authored non-nullable boolean default of false; explicit null is invalid. Read timestamps are normalized to PostgreSQL microsecond precision before comparison, so nanosecond input replay is idempotent. Exact timestamp/notify replay does not rewrite audit or timestamps. Read-all advances only rows whose latest visible public content is newer, and counts changed rows. Receipts are per subscriber. Manager subscriber responses retain the source subscription object, including that publisher's subscriber receipt, behind the manager-only roster boundary.

Latest content combines visible, published public posts excluding replies with public started streams (including ended streams). Drafts, scheduled future posts, private/unlisted streams, deleted content, hidden publishers/realms and account blocks cannot introduce unread indicators. Listing and per-publisher read status use the same computation. IsLive requires a public current active stream, and `/subscriptions/live` returns only subscribed active public streams, ordered by started time and ID. Existing canonical stream hydration supplies publisher/media/award/output projections when configured; no provider is called and no stream credential is issued. Ordinary composition uses a read-only stream projection even if provider writes are disabled.

## Atomicity and authority

The existing follow row is the only subscription authority. The additive `internal/timelinepg/subscription_state_schema.sql` migration adds receipt and removal-actor columns; both embedded schema composition and the explicit disposable runner include it. Readiness requires the new columns and canonical stream schema. Startup applies no DDL. Rollback to earlier code can leave the additive columns in place; dropping them discards receipt/removal attribution and is not required for code rollback.

New subscription transactions check the original opaque authority proof, live account/session, grants and scopes within the transaction and again before commit. Current actor locks serialize own state and revocation. Canonical realm/publisher locks and fresh manager checks protect admin transitions. Target account NOWAIT locking bounds contention and prevents reversed actor/target waits; contention returns conflict. Canonical personal and realm publisher owners must be enabled and free of an effective disable-account punishment at the current database clock. Subscriber lists, own status, read-all, live indicators and live projections apply that same owner eligibility; a punishment that becomes effective during a publisher wait is rechecked before advancing receipts. Read-all updates and audits are one transaction. Any failing audit or notification enqueue rolls back the entire transition.

Manager addition enqueues the source subscriber_added event into the existing canonical notification outbox in the same SQL transaction. Its stable subscription ID gives one durable source key. The existing worker creates inbox/replay state and honors notification preferences. External=false is fixed; no provider delivery, localization or external push parity is claimed. Notify preference does not claim new post/live fanout.

## Verification and boundaries

Three focused HTTP unit cases cover route ownership, absent-capability failure, identity/permission checks, malformed/duplicate body fields and exact timestamp transport. Ten registered actual-PG cases cover full composed client paths, own/admin separation, pending/ended/blocked/disabled targets, exact read and live projections, notification replay, audit rollback, concurrent adds, manager/session wait revocation, proof expiry rollback, realm departure, and saved-state process restart. The restart case issues one-hour synthetic bearers before target state, saves only original public verifier material plus elapsed-wall-clock reference, and creates no replacement target state or credentials after restart.

Local Go, source hash, registry and PostgreSQL-16 grammar checks are offline evidence only. All real PostgreSQL cases are skipped locally without an authorized disposable DSN; only coordinator private CI may establish real before/restart/after acceptance.

Still outside this bounded slice: publisher-specific block/mute and relationship routes, federated follower publishers, original numeric shared subscription-state/end-reason wire values, latest_posted_at ordering, automatic post-read receipts, external notifications and provider/production deployment. Existing owned string-state compatibility is preserved. Full upstream/platform parity is not claimed.
