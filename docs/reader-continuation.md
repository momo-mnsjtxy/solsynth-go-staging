# Reader and link-preview continuation

This slice is based on `8e223ab2b1e88816d910c01fff9feff5900a20e1`. It implements the three authored WebReader REST operations, a bounded metadata parser and optional outbound adapter, and a PostgreSQL cache with atomic privileged invalidation. Host/CLI integration belongs to the integration owner; this delivery does not modify those shared files.

## Source-supported contract

Pinned authored source and exact blobs are in [reader-source-evidence.json](reader-source-evidence.json). The controller exposes anonymous `GET /api/scrap/link?url=...`, `DELETE /api/scrap/link/cache?url=...`, and `DELETE /api/scrap/cache/all`. Both deletions require `cache.scrap`. Solian calls `/scrap/link` with the URL as a query parameter and treats failed previews as absent. Its authored post widget reads the URL, title, description, image URL and favicon from the preview.

The full authored service establishes Open Graph, Twitter, JSON-LD, metadata, title/heading/paragraph and image fallback precedence; metadata dates and authors; non-HTML host/title/content-type fallback; and a default 24-hour cache lifetime. The owned JSON projection is `url`, `title`, `description`, `image_url`, `site_name`, `content_type`, `favicon_url`, `author`, and `published_date`. Optional fields are JSON null. Exact excluded Shared/SDK model serialization is not claimed as legacy parity.

The authored `ScrapedArticle` record and gRPC service expose article HTML internally. This bounded REST slice does not add an unevidenced article endpoint or reproduce excluded generated gRPC contracts.

## Explicit owned policy

- Only exact configured HTTPS origins on port 443 are accepted. Hostnames are ASCII DNS names; IDNs must use their ASCII form. Credentials, IP literals, local host suffixes, malformed authority, control characters, backslashes and unconfigured origins fail closed. Path/query case, encoded slashes, plus signs and trailing slashes are preserved. Fragments are removed. Query decoding happens once; the upstream double-decoding and case-folding cache behavior is not reproduced.
- Every hop resolves DNS, rejects the whole answer set if any address is unsuitable, and dials one checked numeric address with TLS verification for the original host. Local/private/shared/documentation/translation/reserved address ranges are excluded. IPv6 is restricted to assigned global unicast space with special-use exclusions. There is no ambient proxy, incoming-cookie/header forwarding, credential jar, redirect automation, compression or downgrade to HTTP.
- The host explicitly chooses the outbound adapter. Default adapter settings are 3 seconds, 2 MiB and eight concurrent fetches; redirect count must be supplied (recommended three, supported zero through five). Constructors do no outbound work. Each hop uses a fresh transport and the entire chain shares one deadline. Response bodies, headers, parser token count, token size, nesting and extracted fields are bounded.
- HTML must be UTF-8 (or ASCII-compatible declared ASCII). Extraction executes no scripts and fetches no images, favicon, canonical URL or other assets. Output image/favicon URLs must satisfy the same configured URL policy. Canonical URLs must additionally retain the final response origin; relative metadata resolves against the final response URL. Raw article HTML is never returned. JSON-LD is bounded and malformed/nonobject records are ignored.
- Cache reads are anonymous because the upstream fetch is anonymous and limited to explicitly configured public destinations. Cache deletion always performs a fresh same-pool canonical authority check in its own transaction. Merely supplying an actor ID cannot authorize it.

## Durable cache and transaction behavior

`internal/readerpg/schema.sql` adds `owned_reader_cache_state`, `owned_reader_cache`, and `owned_reader_cache_audit`. Install it after canonical authority accounts. Cached previews contain bounded JSON metadata and timestamps; audit rows retain actor, operation, URL hash where applicable, generation and time. They do not retain the complete URL query in the audit record.

A cache miss observes the global invalidation generation, fetches without holding any SQL transaction or row lock, and fills only after locking/rechecking that generation. Either invalidation operation increments the durable generation and commits its deletion plus audit atomically. A stale in-flight fill returns conflict and stores/returns no preview. URL invalidation preserves unrelated existing hits while also fencing all currently in-flight fills. Cache hits linearize at their single joined SELECT. A cached projection is rechecked against the current configured URL policy.

The lock order for invalidation is canonical authority account/proof, then cache state, then cache entries/audit. Anonymous fills take only cache state then entries. The state lock serializes capacity checks and writes across processes. Expired entries are pruned transactionally before a fill; failed fills also roll back that pruning. Defaults are 24-hour TTL and 5,000 rows, configurable up to 24 hours and 10,000 rows. At capacity a new distinct key fails busy. A nil fetcher permits valid cache hits and guarded purges, but misses return unavailable.

## Integration owner wiring

1. Add optional application reader configuration containing `reader.Policy`, `reader.Fetcher`, TTL and maximum cache entries. Keep the default disabled, including a 503 handler for the three known reader routes. Reject separate authority/domain SQL pools when this feature is enabled.
2. Construct with `readerpg.New(db, guard, readerpg.Config{Policy: policy, Fetcher: fetcher, TTL: ttl, MaxEntries: maxEntries, Now: c.Authority.Now})`. Serve `reader.NewHandler(repo, postIdentity{identity{v}})` inside `bindIdentity(v, bindTransactionAuthority(guard, ...))`. Route `/api/scrap/*` for sphere and canonical API scopes, preserving the existing `/sphere/` gateway rewrite. Route nothing under other service prefixes.
3. Add `repo.Ready(ctx)` to readiness only when configured. Constructors never migrate. Install the schema in the disposable runner and include its three tables in the schema gate. No periodic worker is required; fills prune expired records.
4. Suggested CLI flags: `--enable-reader`, `--reader-origins` (exact comma-separated HTTPS origins), and separate `--reader-fetch` for outbound enablement. Reject dependent settings without feature enablement; reject empty origins. Only when both flags permit it construct `readerfetch.New(readerfetch.Config{Policy: policy, Timeout: 3*time.Second, MaxBytes: 2<<20, MaxConcurrent: 8, MaxRedirects: 3})`. Do not enable outbound implicitly for tests or cache-only deployments.
5. Add all five `TestPGReader*` cases below to the required before phase, and the restart case to the after phase and selection regex. Add a host recorder case with a synthetic `reader.Fetcher` proving gateway mapping, disabled defaults, anonymous GET, guarded DELETE, rejected forged account headers, and missing/revoked authority. No live HTTP listener is needed.

## Verification and limitations

New guarded PostgreSQL cases are `TestPGReaderCacheLifecycleAndIsolation`, `TestPGReaderInvalidationFencesInflightFetch`, `TestPGReaderCacheCapacityAndAtomicRollback`, `TestPGReaderInvalidationFreshAuthorityAndPool`, and `TestPGReaderRestartPersistence`. They cover exact cache keys, TTL, cache-only reads, no authority inferred from actor strings, both invalidation races, no SQL locks during fetch, bounded durable capacity, exact audit/fill constraint rollback, revocation/grant changes during a real account-lock wait, guard pool mismatch and restart durability. Restart checks use persisted synthetic timestamps rather than short wall-clock deadlines.

Focused URL/parser/HTTP/transport tests use synthetic strings, DNS results and in-memory response bodies. They perform no external request or socket operation. They cover metadata precedence, malformed/bounded JSON-LD/HTML, unsafe URL omission, redirect/address checks, response limits, concurrency limits and non-HTML previews.

The parser uses official cached `golang.org/x/net v0.56.0`. Its approved compatible dependency resolution upgrades `golang.org/x/text` from v0.29.0 to v0.40.0 and `golang.org/x/sync` from v0.17.0 to v0.22.0. Existing dependency modules remain present; module Go version remains 1.25.0. Resolution and module verification ran offline with Go 1.26.4.

Full `go test ./...`, full vet, focused race checks and `go mod verify` passed. PostgreSQL cases compiled but explicitly skipped without the disposable runner; they require integration CI execution. The unchanged source-evidence and schema-wiring checks pass. The exact-case integration guard intentionally reports the five new cases missing until the integration owner registers them; it must pass after the shared harness integration. Host/CLI wiring and its new host recorder case remain with the integration owner. No live preview fetch, external provider, database or socket was used locally.

The optional host and CLI are now composed with explicit enablement, exact origin settings and independent outbound opt-in.
