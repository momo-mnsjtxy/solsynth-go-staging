# Canonical timeline, discovery, post context and watches

This continuation adds actual PostgreSQL-backed service handlers to the owned backend. It does not claim full legacy Sphere parity. No excluded Shared/Spec/NeTo/SDK-generated definitions or canceled SoSYS repositories were used. The existing licensed ranking and discovery selectors remain the algorithm authority; posts, publishers, accounts, social relationships, taxonomy, reactions, bookmarks and collections retain their existing canonical stores.

## Composition and explicit installation

Install `timelinepg.Schema` after the canonical authority/account/post/social schemas, owned taxonomy and interaction schema. Startup must not migrate. The schema owns only post relation links, publisher follow state and follow-approval policy, discovery interests/preferences, watch preferences and an audit ledger. All resource identities reference or are validated against canonical stores; it creates no second post, publisher or account table.

Compose `timelinepg.NewWithAuthority(db, guard).WithVisibility(social).WithAssociations(interactions)` and use that object as `postpg.WithAssociations(...)`. Route `timeline.Handles(request)` to `timeline.NewHandler(timelineRepository, verifiedHostAuth)` before canonical post/account fallbacks. The same canonical post handler still creates, edits, publishes and deletes posts. Host aliases such as `/sphere` remain host-owned. `New` uses canonical `socialpg` visibility by default; an explicitly nil visibility provider fails closed. `NewWithAuthority` with a nil guard also fails closed. The standalone verified handler binds the opaque proof for transaction revalidation.

The only shared edits are relation/projection fields in `posts.Post` and `posts.Patch`, decoding the three authored relation inputs, their UUID/conflict validation, and explicit rejection when a post association adapter is absent. Existing tag/category/collection/reaction hydration is wrapped, not replaced.

## Implemented HTTP surface

- `GET /api/timeline`: anonymous/public and authenticated feeds; `mode=personalized|top|latest`, `filter=subscriptions|friends`, publisher and collection scope, bounded `take`, cursor and aggressive flag. Empty subscription/friend sets produce an empty feed, never a public fallback. Event fields follow authored Solian `posts_pod.dart`: `id`, `type=posts.new`, `resource_identifier`, `data`, `created_at`, `updated_at`, `deleted_at`. Empty pages contain an `empty` event and null cursor.
- `GET /api/posts`: literal case-insensitive search across title/description/content; publisher, type, tags, categories, inclusive Unix-second periods, reply-only/non-reply filters, date/rank order, offset/take and visibility-filtered `X-Total`. SQL wildcard characters in user text are escaped. Repeated tag/category parameters are supported. Unsupported semantic search, realms, mentions, true media/pinned/shuffle requests return 501 instead of silently becoming another search.
- Canonical post create accepts `replied_post_id`, `forwarded_post_id`, `chained_post_id`; delete/update/publish continue through the existing canonical lifecycle. Relations are immutable after creation. Chaining is flat and limited to the same publisher; chains cannot also be replies/forwards. Text content remains required by the bounded text-post contract.
- `GET /api/posts/{id}/replies`, `/forwards`, `/replies/threaded`, `/thread`, `/chain`: visible anchors, independently visible descendants, source response envelopes, stable ordering and bounded traversal. Thread ancestors stop at an inaccessible node rather than exposing lineage through it. Depth is at most 50, thread pages at most 100, flattened threaded-reply responses at most 500. A larger unpageable flat response fails explicitly. Chains return at most 101 posts including the head.
- `GET /api/publishers/{name}/subscription`, `POST .../subscribe`, `POST .../unsubscribe`, `GET /api/publishers/subscriptions`, `GET .../subscription/requests`, `POST .../subscription/requests/{requestId}/approve|reject`: guarded durable follow/request lifecycle, manager-only request decisions, cross-publisher request-ID scoping, duplicate-subscribe idempotency, account disable/deletion/block filters, and cleanup after blocking. A follow never grants private/friend/close-friend access.
- `GET /api/timeline/discovery/profile`, `POST .../uninterested`, `DELETE .../uninterested`, `POST .../feedback`, `PUT .../weights`, `POST .../reset`: actor-specific durable interests and suppression, clamped weights, decayed ranking, source feedback distribution over canonical publisher/tag/category/collection associations, and atomic reset seeding from active follows and taxonomy subscriptions. The delete route accepts either controller query parameters (`kind`, `referenceId`) or the authored Solian JSON caller (`kind`, `reference_id`), rejecting ambiguous dual input.
- `GET|PUT /api/posts/watch`: licensed default preferences and partial-merge behavior, with actual canonical account storage and `post.subscriptions.manage` authorization. Empty updates still recheck proof. An internal watcher resolver joins canonical bookmark/reaction/reply/chain records, excludes disabled accounts, and rechecks each recipient's post visibility and bilateral blocks. It does not send notifications.

All handler responses are private/non-cacheable. JSON is bounded, rejects unknown fields and duplicate keys at every nesting level, and never accepts submitted identity. Query parameters are validated instead of passed through as SQL. Missing scope resources use controller-observed `PUBLISHER_NOT_FOUND` and `COLLECTION_NOT_FOUND` errors.

## Privacy and concurrency

Canonical `postpg.DetailPredicate`, `ListingPredicate` and social visibility enforce active publisher/account state, drafts, publication time, owner/editor access, unlisted detail-only behavior for outsiders, mutual friendships, owner-directed close-friend status and bilateral blocks. Counts and hydration share repeatable-read snapshots. Every nested relation is independently checked; hidden or deleted targets redact both nested content and target IDs. Visible chained children are hydrated under the head without recursive expansion. Thread descendants cannot traverse an invisible parent.

Writes use the canonical authority row lock and transaction guard before domain changes. Relation links and their audit join the already-guarded canonical post transaction, so target rejection or audit failure rolls back the post and all associations. Publisher locks serialize follow decisions and publisher membership/deletion; post target locks serialize link creation against deletion/visibility changes. Conflicting transactions may return a PostgreSQL retryable error rather than partially commit. Preferences and interest updates serialize on the actor row across independent pools. Foreign request IDs, pending invitations, revoked manager membership, disabled identities, stale proofs and audit failures cannot commit unauthorized state.

Following approval is explicit deployment configuration in `owned_publisher_follow_policy`; absent policy means open following. No premium entitlement, ActivityPub lock, or private-content grant is inferred. Publisher feature/entitlement management remains outside this slice.

## Deliberate independent policies and remaining contracts

The service accepts the legacy ISO timestamp cursor but returns a versioned opaque `(published_at, UUID)` cursor. It ranks a complete chronological page rather than the upstream two-times oversample, so equal timestamps and score reordering cannot lose an unselected page member. Ranking uses the existing base formula, reaction attitudes (positive 0, neutral 1, negative 2), visible thread-reply counts, canonical publisher follows, decayed interests and taxonomy-subscription bonuses. The aggressive flag is passed to the existing selector; it does not remove items from this bounded complete-page pool. This is an independent pagination policy, not exact upstream sampling parity.

`searchEngine=fulltext` is an owned literal substring implementation, without pg_trgm or semantic embeddings. Relevance/semantic search and legacy fuzzy ranking are not claimed. Ranking has no fabricated automated-account, automod, sponsor, rating, realm or federated signal. Those providers are not installed in this slice.

The authored Solian publisher/profile and creator request UI use SDK-provided `isActive`/`isPendingRequest` getters and status strings. The permitted authored tree does not define numeric subscription-state mappings; the excluded SDK was not opened. This implementation uses independently defined string `state` values `pending`, `accepted`, `rejected` and emits the observed status/boolean fields. Numeric legacy state interoperability remains an explicit client-contract gap, not a parity claim.

Discovery publisher suggestions compose the existing source selector over recent public canonical posts. Account/realm suggestions, generated status/presence events, ads, federation boosts and external notification effects are absent, not fake provider calls. Suppressed entries have the source suggestion envelope with safe ID labels; they do not reload deleted/private target metadata. Reset seeds current subscriptions; upstream own-post history seeding is not implemented. Subscription live state is false because this owned slice has no live-stream records; unread content currently reflects any visible canonical top-level content without a subscription read-state protocol. Notify toggles/read-status/live/subscriber-admin routes remain unsupported. Watch preference persistence and recipient resolution are complete; notification delivery orchestration remains separate.
